# 40. AI colonists

The bots are the product (CLAUDE.md). This spec defines how a bot seat decides everything a human
seat decides, from its own view only. Personas, knob values and table talk are in
`41-personas-and-talk.md`; rules are in `10-rules-core.md`; objectives in `11-objectives.md`.

**Source keys.** `H.n` / `C.n` = brief sections (`docs/DEAD-OF-WINTER-HANDOFF.md`). Rule clauses are
cited by `10.x.y` / `11.x`, which cite the rulebook (`R pN`) and FAQ (`F x.y`). Everything here that
is not cited is our design (marked by its section only). No web sources were used.

**Units.** All utilities are in **morale points (MP)**: 1 MP = 1 morale on the track. Probabilities
are in [0, 1]. Knobs from personas are in [0, 1] (41.2).

---

## 40.0 Goals and non-goals

- 40.0.1 A bot performs every decision kind in 10.15 for its seat, from `view(state, seat)` only.
  (H.1; C.4)
- 40.0.2 The table must read as people: loyal bots cooperate visibly, argue about the crisis, and
  vote on evidence; a betrayer is findable from public tells but not obvious. (H.3; H.8)
- 40.0.3 No runtime LLM, no network. Everything is closed-form maths, a small beam search and
  pre-written lines. (H.6)
- 40.0.4 Bots never cheat, at any tier (40.11). Harder tiers search deeper and estimate better;
  they never see more.

## 40.1 Architecture

- 40.1.1 **Module layout** (`src/ai/`, C.2):

  | File | Owns |
  |---|---|
  | `host.ts` | `createBotDecider(seat, persona, tier, seed)` implementing the frozen `Decider`; builds the bot context; enforces the budget |
  | `belief.ts` | the bot's private memory: hand models, deck models, contribution ledger, claims, suspicion state |
  | `odds.ts` | closed-form odds: exposure, bite chain, search hit, noise, attack-a-survivor, sample roll |
  | `forecast.ts` | `forecastColony(est)`: expected colony phase outcome (food, waste, crisis, zombies, overruns) |
  | `utility.ts` | goal vector features and role/persona weights (40.2) |
  | `planner.ts` | turn planner and dice knapsack (40.3) |
  | `crisis.ts` | crisis contribution (40.4) |
  | `suspicion.ts` | suspicion model (40.5), also run in "observer mode" by `betrayer.ts` |
  | `votes.ts` | vote calls, leans, casts, tiebreaks (40.6) |
  | `requests.ts` | making and answering requests (40.7) |
  | `betrayer.ts` | hidden/visible channel weights and the cover budget (40.8) |
  | `minor.ts` | every other decision kind by one-step lookahead (40.9) |
  | `tiers.ts` | tier parameter table (40.10) |
  | `budget.ts` | node and wall-clock budgets (40.12) |
  | `talk.ts` | trigger selection, rate limits, claims (spec 41) |
  | `worker.ts` | Web Worker entry for the client (40.1.6) |
  | `random.ts` | the Random tier (40.10.2) |

- 40.1.2 **Input boundary.** The host implements the frozen `Decider` (`src/engine/decider.ts`):
  `decide(view, decision, ctx)` receives a `PlayerView` (from the engine's `view(state, seat)`), the
  open decision as a `ViewDecision` (with `context`, `legal` and `annotations` present because it
  is this seat's), and a `DecideContext`; nothing else from the engine. It never imports engine state types
  beyond `view.ts` exports, and never holds a reference to `GameState`. A lint rule bans
  `src/ai/**` from importing anything in `src/engine/` except `types`, `actions`, `events`, `view`,
  `decider`, `rng` and pure rule helpers re-exported by `index.ts` for odds (exposure faces,
  thresholds). (C.4; 10.0.6)
- 40.1.3 **Output.** The host returns exactly one element of `decision.legal` (deep equality,
  `actions.sameAnswer`). If the planner produces anything else, the host logs `AI-ILLEGAL` (bench
  hard fail) and returns `fallbackAnswer(decision)` from `decider.ts` instead: `endTurn` for a turn
  decision, else `decision.legal[0]`.
  (10.0.7)
- 40.1.4 **Memory.** The bot's belief state (`belief.ts`) is updated only from (a) the redacted
  `SeatEvent`s in `ctx.events` since the bot's last call, plus the view itself, and (b) the public
  talk entries in `ctx.talk` (41.5). A bot rebuilt mid-game from the same view sequence reaches the
  same belief state (replay-safe; resume from save works).
- 40.1.5 **Talk log as a side channel.** Talk lines, claims and human accusations are not engine
  state and never change rules. The client/sim keeps the talk log as `TalkEntry[]` (41.5.1) and
  delivers the entries since a bot's previous call in `DecideContext.talk`: on `decide(view,
  decision, ctx)` when the bot is answering, and through the optional `observe(view, ctx)` (events
  and talk, no budget) after every step when it is not. Each bot host implements `observe` so its
  belief stays current between its own decisions. There is no other talk channel.
- 40.1.6 **Where bots run.** Sim and bench: synchronously in Node. Client: in one Web Worker
  (`worker.ts`) that holds all bot hosts; messages carry the JSON view and the decision. The UI
  thread never blocks on a bot.
- 40.1.7 **Simultaneous votes.** For a `seat:'all'` vote decision the client asks each
  bot with its own view, which never contains other seats' votes. Bots' answers are produced before
  or independent of the human's answer and are not shown until `castVotes` resolves. (C.4; 10.12.3)
- 40.1.8 **Bot RNG.** Each bot owns a decision RNG forked from the game seed with label
  `ai/<seatId>` (and `ai/talk/<seatId>` for talk). These streams never draw from the game RNG, so a
  bot's tie-breaks and persona noise never move the dice the human sees. (H.9) The driver passes the `deriveSeed` result only to bots; human seats get no seed.
- 40.1.9 **Hidden log.** Every non-trivial decision appends `{round, kind, chosen, why, scores?}`
  to the bot's hidden log (`why` is a short enum + numbers, e.g. `crisis:wrongSymbol cover=0.12`).
  The end recap shows it (H.3; 10.13.3). Never shown before `GameEnded`.

## 40.2 Goal vector and utility (H.2)

- 40.2.1 `U(est) = Σ_k w_k(role, persona) · f_k(est)` over an **estimated state** `est` (the view
  plus belief-model expectations for hidden parts). Features, all in MP:

  | id | Feature | Definition |
  |---|---|---|
  | f1 | morale | current morale + expected morale change from `forecastColony` |
  | f2 | food | −expected starvation morale loss at this round's pay (10.4.7), plus 0.3 MP per food token above next round's need (cap 3) |
  | f3 | waste | −P(crossing the next multiple of 10 before colony phase) · 1 |
  | f4 | colony threat | −expected overrun deaths at the colony this colony phase × 1.2 (death costs 1 morale plus dice) |
  | f5 | own-location threat | −expected overrun deaths at the seat's non-colony locations × survivor value |
  | f6 | crisis | P(prevent) · failCost + P(total ≥ players + 2) · 1, where failCost is the crisis card's failure effect valued in MP (data `aiFailCost`, default 2) |
  | f7 | main objective | progress value: samples × (V_main / target); V_main = 6 |
  | f8 | secret objective | `V_secret · progress(predicate)` (40.2.4), times P(main completes) when the predicate includes the main clause (11.4.1) |
  | f9 | survivor safety | −Σ survivors (P(death) · value(s) + E[wounds] · 0.2) |
  | f10 | hand quality | Σ cards in hand of the best use value (crisis match, objective need, playable effect) |
  | f11 | public image | −Σ observers Δ(observer's suspicion of me) · imageCost (40.8.4) |

- 40.2.2 **Survivor value** `value(s) = 1 (morale on death, 10.9) + 0.5 · roundsLeft (lost die) +
  abilityBonus(s)` (data `aiAbilityValue`, default 0.5); helpless tokens = 0.6.
- 40.2.3 **Role weights** (persona knobs adjust them in 41.3):

  | Role | colony f1–f7 | secret f8 | safety f9 | hand f10 | image f11 |
  |---|---|---|---|---|---|
  | loyal | 1.0 | 0.6 | 1.0 | 0.4 | 0.2 |
  | betrayer, hidden channels | −1.0 | 1.0 | 0.6 | 0.6 | (n/a) |
  | betrayer, visible channels | +0.5 | 1.0 | 0.6 | 0.6 | 1.0 |
  | exiled loyal | 0.3 | 1.0 (exiled objective) | 1.0 | 0.6 | 0 |
  | exiled betrayer | −1.0 | 1.0 | 0.6 | 0.6 | 0 |

  An action is on a **hidden channel** if its sabotage content is invisible in other views
  (face-down contribution symbols, which cards it keeps, the true reason for a decline); visible
  channels are everything others see (40.8.1).
- 40.2.4 **Objective progress** `progress(p) ∈ [0, 1]` is derived from the DSL predicate: counts
  (`handCount(symbol, n)`, `controlsSurvivors(n)`, ...) give `min(have, n) / n`; booleans give 0/1;
  conjunctions multiply; `gameEndedBy='morale'` uses `1 − morale / startMorale`. V_secret = 4 MP.
  The predicate is read from the bot's own objective in its view (it is always visible to its owner).
- 40.2.5 **Hand model** for each other seat: a probability vector over item symbols per unknown
  card, built from location-of-origin priors (a card kept from a search at location L is drawn from
  L's remaining composition), minus cards seen publicly (played, revealed by requests, crisis
  reveals are aggregate only), with known cards (stolen by this bot via attack, given to this bot)
  pinned. Used for request answering odds, crisis estimates and suspicion evidence.
- 40.2.6 **Deck model** per location: composition from data (public) minus every card the bot saw
  leave that deck (public plays traced to the deck, its own draws). Cards the bot itself put on the
  bottom are excluded from the next `deckSize − bottomCount` draws. Search hit chance uses this
  model (H.2).

## 40.3 Turn planner and dice knapsack (H.2)

- 40.3.1 The turn decision is answered **one action at a time**. On each `turnAction` call the
  planner builds a full plan for the rest of the turn, returns only its first action, and discards
  the plan. The next call re-plans from the new view (searches, exposures and bites change the
  state). (C.4)
- 40.3.2 **Candidate actions** per survivor `s` and die `d` (10.5): attack zombie (`d ≥ atk(s)`,
  zombie present), search (`d ≥ search(s)`, deck non-empty), barricade, clean waste (colony),
  attract, ability `(N+)`; and die-free actions (10.6): move (≤1 per survivor), play card,
  contribute (handled in 40.4 as the plan's final step), spend food (+1 to a die), request (40.7),
  hand off, call vote (40.6), end turn.
- 40.3.3 **Knapsack rule.** Dice are sorted ascending; an action takes the **lowest** unused die
  that meets its threshold. A food boost is considered only when it lifts a die across a threshold
  that the plan needs and no unused die already meets it (10.6.4). Spare low dice go to the
  any-die actions (barricade, clean waste, attract) in that order of value.
- 40.3.4 **Beam search.** Node = (unused dice, survivors moved, partial plan, `est`). Expand by
  every candidate action (dominated ones pruned by 40.3.3); score children by
  `U(apply_expected(est, action))`; keep the best `beam` nodes per depth (tier: 40.10). Leaf =
  plan ends with `endTurn`; leaf score = `U(forecastColony(est))`. Max depth = dice + survivors + 3.
  Ties broken by the bot RNG.
- 40.3.5 **Expected application.** Stochastic actions are applied in expectation over their closed
  outcomes (40.3.6–40.3.9), except death, which uses its probability-weighted value. No Monte Carlo.
- 40.3.6 **Exposure** (10.7.1): P(blank) 6/12, wound 3/12, frostbite 2/12, bitten 1/12. Death
  probability for a survivor with `w` wound+frostbite tokens: bitten + (w ≥ 2 ? 5/12 : 0). Bite chain
  expected extra deaths at destination L: `Σ_k (1/2)^(k−1) · 1/2` over the k lowest-influence other
  survivors at L, valued with their owners' survivor values (other seats' deaths still cost morale).
  Frostbite adds 0.25 MP per remaining round (start-of-turn wound, 10.4.4b).
- 40.3.7 **Search** (10.5.3): P(card i useful) from the deck model; keep-or-noise stop rule: draw
  again while `E[max value of k+1 cards] − E[max of k] > noiseCost(L) · (1.5 − riskAppetite)`, with
  `noiseCost(L) = 1/2 · zombieCost(L)` and `zombieCost(L)` = marginal overrun risk of one more zombie
  at L next colony phase (10.8.6.3). Requires an empty noise space (10.2.3).
- 40.3.8 **Attack a survivor** (10.5.2): P(hit) = atk(target)/6 (re-roll ≤ target's attack value).
  Loyal bots consider it only against a seat with suspicion ≥ 0.6 that likely holds a needed card,
  or when the bot's objective requires it; betrayers per their objective.
- 40.3.9 **Sample roll** (11.3.4): every zombie kill adds 1/2 sample in expectation.
- 40.3.10 **Movement risk** (H.2): a move's cost is its exposure term (40.3.6) plus the loss of
  the colony seat count change (food need, colony zombie adds). Moves are proposed only to locations
  whose score `searchValue(L, needs) − threatAt(L)` beats staying by more than the move's cost;
  `needs` = crisis prevent symbol, own objective symbols, food when food is short. Default: survivors
  stay home when no die is worth spending.
- 40.3.11 **Colony forecast** `forecastColony(est)` (10.4.7–10.4.12): food pay and starvation
  morale; waste threshold crossing; crisis outcome distribution from the contribution estimate
  (40.4.2); colony and per-location zombie adds with barricades and overrun deaths (10.8.6), noise
  adds at P 1/2 each; main objective completion check. Deterministic expectations; O(locations).
- 40.3.12 **Mid-turn free actions.** Hand off and play-card are expanded only when they change a
  later action's feasibility or a feature by ≥ 0.1 MP; this keeps the branching small.
- 40.3.13 **Termination.** A plan step that does not change `est` is never generated, so every turn
  ends; the host also forces `endTurn` after 40 actions in one turn (`AI-STUCK`, bench warning).

## 40.4 Crisis contribution (H.2)

- 40.4.1 Contribution is the plan's last step before `endTurn` (10.4.13; 10.6.2), so the bot uses
  everything learned this turn. Seats later in the round know more; bots exploit that by default.
- 40.4.2 **Estimate.** `players` = non-exiled seats (10.4.15). For each other seat `j`:
  - already contributed `c_j` (visible count per seat; 10.4.16): value `c_j · (2 q_j − 1)` with
    `q_j = (1 − P_j) · qLoyal + P_j · qBetrayer`, `qLoyal = 0.9`, `qBetrayer = 0.35`, `P_j` = this
    bot's suspicion of `j` (40.5); a trusted claim (41.5) replaces `q_j` by the claimed share,
    weighted by trust;
  - not yet acted this round: expected future value `= P(holds ≥1 match, hand model) · g_j`, with
    `g_j` = observed contribution rate of `j` in earlier crises (prior 0.7).
  `E_total` = own contributions so far + Σ_j. Hard tier also tracks the variance (independent
  Bernoulli sum) and uses `P(total ≥ players)`; Easy uses `E_total` only.
- 40.4.3 **Loyal rule.** Contribute `k` matching cards where `k` is the smallest number giving
  `P(prevent) ≥ targetP` (Normal/Hard; `targetP = 0.80 + 0.1 · (1 − riskAppetite)`) or
  `E_total + k ≥ players + margin` (Easy; margin 0). Then add the +2 bonus cards only if every extra
  card has `useValue < 1` MP elsewhere.
- 40.4.4 **Reserved cards.** Cards the bot's secret objective counts (40.2.4) are reserved: never
  contributed unless crisis failure would drop morale to 0 (then colony survival wins) or the
  objective is judged unreachable (`progress` cannot reach 1 in the remaining rounds by the
  planner's best estimate). Never over-contribute reserved cards (H.2).
- 40.4.5 **Equipped items** may be contributed (10.6.2); they are valued at their equip value.
- 40.4.6 **Off-symbol cards.** A loyal bot never contributes an off-symbol card (it is −1, 10.4.14).
- 40.4.7 **Announcement.** After contributing, the bot may emit `crisis.claim` (41.4) with chance
  `chattiness`. Loyal bots claim truthfully or stay silent. Betrayers follow 40.8.3.
- 40.4.8 **Exiled seats** never contribute (10.11.4); the decision is not generated for them.

## 40.5 Suspicion model (H.4)

Every bot runs this on every other seat, including the human.

- 40.5.1 **Hypotheses.** Belief is a distribution over `H ∈ {none, s_1 … s_m}` (the other seats):
  at most one betrayal card is dealt (11.4.4). Priors given the bot's own objective is loyal:
  standard deal (2n standard + 1 betrayal, n seats): `P(s_j) = 1/(2n)` each, `P(none) = 1 − (n−1)/(2n)`
  (n=4: 0.125 each, none 0.625). Betrayer variant (10.14.3): `P(s_j) = 1/n` each, `P(none) = 1/n`.
  `suspicion(j) = P(H = s_j)`.
- 40.5.2 **Update.** For evidence `e` attributed to seat `j`: multiply `P(H=s_j)` by
  `LR_e ^ paranoia'` and renormalize, where `paranoia' = 0.5 + paranoia` (41.2) and `LR_e` is from
  40.5.3. Evidence against nobody in particular does nothing. Each update's log-ratio is clipped to
  ±log 6 so one event never decides a vote alone.
- 40.5.3 **Evidence table** (defaults; tunable in `tiers.ts`, recorded in the bot's hidden log):

  | id | Evidence | Attribution | LR |
  |---|---|---|---|
  | EV-CRISIS | revealed off-symbol cards `neg` (10.4.14) | subtract the bot's own off-symbol count; split the rest over other contributors pro rata `c_j · w_j`, `w_j = 1 − 0.5 · trust · claimedMatching_j` | `4 ^ share_j` per attributed card |
  | EV-CLAIM-LIE | a claim the arithmetic contradicts (e.g. `j` claimed all matching and is the only other contributor, `neg > own`) | `j` | `6 ^ trust` |
  | EV-NOSHOW | crisis failed, `j` contributed 0, hand model P(j held a match) = h | `j` | `1 + h` |
  | EV-DECLINE | `j` declined a request; hand model P(j held the card) = h | `j` | `1 + h` |
  | EV-GIVE | `j` gave on a request | `j` | 0.8 |
  | EV-XROADS | `j` chose a Crossroads option worth Δ MP less to the colony than the other, Δ ≥ 0.5 | `j` | `min(3, 1.5^Δ)` |
  | EV-ATTRACT | `j` attracted zombies to a location holding other seats' survivors, or moved survivors so zombies are added where others stand | `j` | 1.5 |
  | EV-HUNGRY | starvation token added while `j` likely held a food card (h ≥ 0.5) and did not play it | `j` | `1 + 0.6h` |
  | EV-FOODBURN | `j` spent food tokens on dice while the colony could not pay this round | `j` | 1.4 |
  | EV-ATTACK | `j` attacked a survivor of a seat the bot rates loyal | `j` | 1.6 (2.0 if the victim is this bot) |
  | EV-WASTE | `j` played a card that pushed waste over a multiple of 10 when another play was open | `j` | 1.3 |
  | EV-HOARD | `j` keeps a public objective-relevant card (seen via request reveal or steal) the colony needed | `j` | 1.3 |
  | EV-VISIBLE+ | `j` killed zombies, barricaded the colony, cleaned waste | `j` | 0.92 per action (cap 3 per turn) |
  | EV-ACCUSE | the human accused `j` (41.6) | `j`; and the accuser | `j`: `1 + 0.15 · (1 − trust)`; accuser: 1.05 if `suspicion(accuser) ≥ 0.3` else 1.0 |
  | EV-VOTE | `j` voted no on a seat later shown to be the betrayer, or yes on a seat later shown loyal (both only through the 40.5.4 inferences; exile reveals nothing) | `j` | 1.4 / 1.2 |

- 40.5.4 **Inferences, not reveals.** Exile reveals nothing: the exiled seat draws a hidden exiled
  objective and the engine applies the two-exile rule silently (10.11.2, 10.11.5; Ruling
  R-EXILEOBJ in 10). Bots infer from the public outcome instead:
  - **Two-exile inference.** Two loyal exiles drop morale to 0 and end the game (10.11.5). So when a
    second (or later) exile resolves and the game continues, the betrayer is among the exiled seats
    `E`: set `P(H = x) = 0` for every `x ∉ E` and renormalize over `E` (one betrayal card at most).
    With exactly two exiled, this collapses suspicion onto that pair; prior evidence still ranks the
    two. A loyal exiled bot that is in `E` knows the other exiled seat is the betrayer
    (`P = 1`).
  - **First exile.** No collapse. Exile is a vote outcome, not evidence of role; only the existing
    evidence terms apply.
  - **GameEnded** reveals every objective (10.13.3). Belief is set to the truth for the recap,
    bench metrics (M4, M5) and post-game talk; no in-game decision follows.
- 40.5.5 **Statements.** Claims enter only through `w_j` and EV-CLAIM-LIE; `trust` scales both.
  A low-trust persona mostly ignores what others say and reads only the arithmetic.
- 40.5.6 **Observer mode.** `suspicion.ts` can be run as "what seat `k` probably believes about seat
  `x`" using only evidence public to `k` (no private knowledge of the running bot), with table-mean
  knobs (paranoia 0.5, trust 0.5) unless `k`'s persona is known (bots' personas are public; the
  human uses paranoia 0.6, trust 0.4). Used by the betrayer (40.8) and by vote-call prediction (40.6).
- 40.5.7 **Easy tier** keeps no suspicion state: it treats every other seat at the prior.

## 40.6 Votes (H.4, H.5)

- 40.6.1 **Cast** (`vote`, simultaneous). A loyal bot votes yes on target `t` iff
  `suspicion(t) ≥ θ + afford(t)`, where `θ = voteThreshold(persona)` (41.3) and
  `afford(t) = 0.15 · dependency(t) · min(1, roundsLeft / 3)`; `dependency(t)` ∈ [0, 1] = the share of
  this round's crisis and colony defence the planner expects from `t` (late rounds: the loss does
  not matter, H.4).
- 40.6.2 **Two-exile guard** (10.11.5; 11.7.6): if one seat `e` is already exiled, a second exile of
  `t` ends the game when both are loyal. With one betrayal card at most,
  `P(game ends) = P(loyal e) · P(loyal t | loyal e) = 1 − P(H = e) − P(H = t)`, using the bot's own
  suspicion estimates. A loyal bot votes yes only if that probability is ≤ 0.15 (equivalently
  `suspicion(e) + suspicion(t) ≥ 0.85`), on top of 40.6.1. A loyal bot that is itself the exiled
  seat `e` knows it is loyal and uses `P(game ends) = 1 − P(H = t)`.
- 40.6.3 A bot never votes to exile itself. If it is the target and loyal, it votes no and emits
  `accused.me` / `vote.target.me` lines.
- 40.6.4 **Calling a vote** (10.12.1, once per turn, as a turn action). A bot calls on the seat `t`
  with the highest suspicion iff `suspicion(t) ≥ θ_call` (41.3; persona-driven, the Hard Case calls
  early) and predicted yes votes (observer-mode suspicion of `t` per seat vs each seat's θ; the
  human predicted at θ 0.45) reach a strict majority including ties broken by the first player's
  predicted vote (10.12.5). It never calls twice on the same target within 2 rounds unless new
  EV-CRISIS or EV-CLAIM-LIE evidence arrived.
- 40.6.5 **Leans** (H.5). Between `vote.called` and the simultaneous cast, each bot emits
  `vote.lean.yes` / `vote.lean.no` with probability `chattiness` (silent otherwise). A loyal bot's lean
  equals its intended vote. The lean is emitted before any vote exists, from the bot's own view, so it
  cannot leak the human's vote.
- 40.6.6 **Tiebreak** (`voteTiebreak`, 10.12.5): same rule as 40.6.1 with `afford = 0`.
- 40.6.7 **Exiled bots** do not vote (10.11.4) but may still call votes (10.12.1); an exiled loyal
  bot calls only at `suspicion ≥ θ_call + 0.1`.

## 40.7 Requests (H.5; 10.6.5)

- 40.7.1 **Rule constraint.** A given card must be played at once and cannot go to the crisis
  (Ruling R-REQUEST in 10). So bots request cards only for an immediate play: food (tokens), medicine
  (heal), weapon/tool (equip), fuel (a move without exposure, per card data), or an ability cost.
- 40.7.2 **Making a request.** Candidate: symbol `x` with `gain(x)` = the planner's utility gain from
  playing one now. Request iff `gain(x) ≥ 0.75` MP and `Σ_j P(j holds x) · P(j gives) ≥ 0.3`. At most
  one request per bot per turn; never re-request a symbol in the same round after everyone declined.
  Exiled bots may request (10.11.4). Prompt text for the human comes from 41.4 `request.ask`.
- 40.7.3 **Answering** (`requestResponse`). Give card `c` iff
  `generosity · gain_requester(c) − ownCost(c) − 1.5 · suspicion(requester) ≥ 0`, where
  `ownCost(c)` = the card's best own use value, with reserved objective cards (40.4.4) costing ×3.
  Among holdable cards of the symbol, give the cheapest. Answers come in turn order (10.6.5); a bot
  whose earlier-answering seat already gave declines automatically when the request is satisfied
  (the engine closes it).
- 40.7.4 **Toward the human.** The human is answered with the same rule, using `suspicion(human)`.
  A bot that the human gave a card to records `EV-GIVE` for the human; a human decline records
  `EV-DECLINE` (H.5).
- 40.7.5 **Talk.** A give emits `request.give`; a decline emits `request.decline` (loyal: truthful
  reason enum `needIt | dontHave | dontTrust`; betrayer per 40.8.3).

## 40.8 Betrayer play (H.3)

- 40.8.1 **Channels.**
  - Hidden, negative colony weight: off-symbol cards into the crisis; keeping cards the colony or the
    betrayal objective needs; declining requests with a plausible reason; picking the morale-costing
    Crossroads option when the gap to the other option is ≤ 1 MP or the costly option has a random
    element ("unlucky" framing).
  - Visible, positive colony weight (cover): killing zombies, barricading, cleaning waste, giving
    cheap cards on requests, contributing visible counts.
- 40.8.2 **Crisis sabotage.** Contribute a mix that maximises expected colony damage per unit of
  expected suspicion: prefer turns where ≥2 other seats have contributed (attribution splits,
  EV-CRISIS) and pair each off-symbol card with ≥1 matching card when the hand allows. Target outcome:
  total just below `players` (failure without an obvious gap). Hard tier computes the exact expected
  attribution each observer would assign (observer mode 40.5.6) and picks the mix with the best
  `damage − imageCost · ΔP`.
- 40.8.3 **Bluffing.** Claims and decline reasons are chosen to minimise observer-mode suspicion:
  the betrayer claims the number of matching cards that keeps EV-CLAIM-LIE impossible from public
  arithmetic, with probability `bluffing`; else it stays silent. It never claims something public
  maths already contradicts (that would be free evidence).
- 40.8.4 **Cover budget.** For each other seat `k`, `P̂_k` = observer-mode suspicion of self.
  `exileRisk` = probability the predicted votes reach a majority if `k` with the highest `P̂_k`
  called now. Budget `B = θ̄ − margin − max_k P̂_k` (`θ̄` = mean predicted threshold; margin: Easy 0,
  Normal 0.10, Hard 0.15). A hidden sabotage action with predicted `ΔP` is allowed iff `ΔP ≤ B`,
  or the **late window** holds. `imageCost` in f11 = 4 MP per 0.1 of `ΔP` above `B`, 1 MP below.
- 40.8.5 **Late window** (exile no longer matters): `roundsLeft ≤ 1`, or morale ≤ the crisis failure
  loss + 1, or the betrayal objective is completable this round. Easy treats every round as late
  (greedy early, H.3). Hard opens the window only on these conditions (patient).
- 40.8.6 **Votes.** Never yes on itself. On an innocent target: vote yes when the prediction says it
  passes anyway (bank image) or when a second loyal exile would end the game (10.11.5; the betrayer
  knows any other exiled seat is loyal) and the betrayal objective wins on morale 0; else vote with its stated lean. Hard betrayers call votes on
  innocents only when predicted to pass and when 40.6.2 makes it game-ending.
- 40.8.7 **Hoarding.** Cards the betrayal objective needs are reserved like 40.4.4 with no
  colony-survival exception.
- 40.8.8 **After exile.** The betrayer keeps its objective (Ruling R-EXILEOBJ) and switches to the
  exiled-betrayer weights (40.2.3); image weight 0.

## 40.9 Other decisions (H.1)

Each is answered by one-step lookahead: score each legal option with `U(apply_expected(est, opt))`.

- 40.9.1 `chooseSurvivors`, `chooseLeader`: survivor value (40.2.2) + fit to secret objective and the
  main objective (high attack for samples) + persona (the Kid weights search, the Hard Case attack).
- 40.9.2 `searchKeepOrNoise`, `searchKeepWhich`: 40.3.7 and best use value; betrayer may keep the
  card the colony needs most when it is a hidden channel.
- 40.9.3 `crossroadsOption`: expected value of each option (random parts in expectation); betrayer per
  40.8.1.
- 40.9.4 `biteSpread` (10.7.5): kill the target (exactly 1 death of value v_t) vs roll (P 1/2 safe,
  else target dies and the chain continues: expected deaths per 40.3.6). Loyal picks the lower expected
  loss; betrayer picks the higher only within the cover budget (the choice is public).
- 40.9.5 `newLeader`, `exilePlacement`: highest survivor value; placement minimises overrun risk
  and maximises search value (10.11.3).
- 40.9.6 `objectiveChoice`, `itemTarget`, `orderEffects`: lookahead; ties by bot RNG.

## 40.11 Fairness rules (H.9; README text)

- 40.11.1 Bots see only their own view; the `VIEW-*` leak test runs on every sim game. (C.4)
- 40.11.2 **Metamorphic leak test** `AI-FAIR-002`: re-deal every hidden part of the state that the
  view hides from the bot (other hands, other objectives, deck orders, the held Crossroads card),
  consistent with the view; the bot's decision must be identical. Runs on 200 sampled decisions per
  bench run.
- 40.11.3 Bots roll on the same seeded game RNG as the human, in turn order; their own decision RNG
  never touches the game stream (40.1.8).
- 40.11.4 Bots never see the human's simultaneous vote before casting (40.1.7).
- 40.11.5 Higher tiers buy computation and better estimation, never information (40.0.4).
- 40.11.6 Talk never states a hidden engine fact the speaker does not know. A bot may misstate only
  its own hidden information (betrayers per 40.8.3); public numbers are always stated as the engine
  gives them.
- 40.11.7 The end recap shows each bot's hidden log (40.1.9): every contribution by card, every
  declined request with its true reason, every betrayer choice. (H.3; 10.13.3)
- 40.11.8 Pacing delays (41.7) are presentation only; they never depend on hidden information.

## 40.12 Per-decision time budget (CLAUDE.md; B.3)

- 40.12.1 Primary budget = **node cap** per tier (40.10.1): deterministic on any machine.
- 40.12.2 Wall-clock cap from the env var **`DOW_AI_BUDGET_MS`** (Node: `process.env`; client build:
  `VITE_DOW_AI_BUDGET_MS`; client override `?aiBudget=<ms>`). Default 250. `0` = no wall-clock cap
  (node cap only). When the cap hits, the planner returns its best complete plan so far and
  increments `budgetHits`.
- 40.12.3 Sim, bench and tests set `DOW_AI_BUDGET_MS=0` by default so results are reproducible from
  the seed; CI runners are slow and must not change outcomes. `bench:ai --budget-ms N` measures
  behaviour under a real cap.
- 40.12.4 The planner must always have a complete plan after its first expansion round (greedy
  completion), so a cap at any moment returns a legal action.
