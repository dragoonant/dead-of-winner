# 40: AI colonists

`src/ai/` implements `Decider` (`00-architecture` §13) for every bot seat. A bot receives only
`(view: SeatView, pending: PendingDecision, legal: Action[])` plus the read-only `query.*` helpers, which all take a
`SeatView` (00 §10). It never sees `GameState`, `state.rng` or another seat's hidden ids; the leak test (B.4) proves
it on every sim game. It runs in a Web Worker in the browser and in-process in `npm run sim` / `npm run bench:ai`.
AI randomness uses `deriveSeed(gameSeed, seat, pending.id, tier)` (`rng.ts`), never the game stream, so a recorded
log replays identically (H.9). Rulebook pages are cited as `R pN`, FAQ v1.1 entries as `F n.n.n`.

## 2. Dispatch per decision kind

Each decision: build candidates from `legal` → drop hard-forbidden ones (§7.4, §8.4) → score with the utility (§3) →
pick the max, ties broken by the AI seed. The bot never returns an action outside `legal`.

| `pending.kind` | Policy |
|---|---|
| `chooseSurvivors` | score each pair of the 4 in `me.offered`: influence of the best leader candidate (first-player token, R p7; tie-breaks on votes, R p11), attack and search values against the main objective's needs, ability value (§10 grant table), persona `risk` tilts toward low-search/high-attack or the reverse |
| `chooseLeader`, `newLeader` | highest influence unless an ability is worth more to the objective (table in §10); the Kid persona takes the highest attack instead |
| `turnAction` | the plan (§4) picks the next action; `endTurn` when no job has positive value |
| `searchKeepOrNoise` | keep if the best drawn card's value ≥ `τ_keep`, else make noise iff `E[gain of one more draw] > cost(noise)` (§4.2, §5) and a noise space remains |
| `searchKeepWhich` | the drawn card with the highest value (§3.4) |
| `crisisContribution` | §6 |
| `requestResponse` | §9.2 |
| `crossroadsOption` | §10; a `vote: true` option is scored with the expected vote result from §8 |
| `biteSpreadOption` | closed-form chain value (§4.2): `roll` when `½·(value(s) + V(next)) < value(s)` from the controller's goal vector, else `kill` |
| `exilePlacement` | each survivor to the non-colony location with the best (search value for the exiled objective − zombie pressure), spaces permitting (F 5.4.1 bumps are the engine's) |
| `votes` | §8.4, one answer per bot from its own view; the client assembles `castVotes` (C.4) |
| `objectiveChoice`, `itemTarget`, `effectChoice` | §10 on each option's `EffectNode[]`, using `pending.options[].odds` and `.cost` when the engine supplies them |
| `gameOver` | `ack` |

## 3. Goal vector and utility

`U(outcome) = Σ_k w_k · Δk` over five components, each measured from the view; `w` depends on the bot's role (which
only its own view reveals) and persona scalars (41 §1).

| Component | What it measures (all via `query.*` or the view) |
|---|---|
| `colony` | morale (−10 per point lost; ×2 when morale ≤ 2), `query.foodNeeded` shortfall and starvation (E.4 step 1, F 6.1.1), waste cards to the next multiple of 10 (E.4 step 2), colony zombie pressure = Σ entrances `zombies / (empty + barricades + 1)` scaled by survivors at the colony (overrun, R p13), zombies at locations holding any survivor, `query.crisis` margin (`minTotal`, `maxTotal` vs `needed`), main objective `parts` progress |
| `objective` | own secret (or exiled) objective `parts` from `query.objectiveProgress`; multiplied by `P(main completes)` when `requiresMain` (E.12); betrayal objectives read their lever from the objective record (§7.1) |
| `safety` | expected survivor value lost to the exposure rolls the plan commits to (§4.2), plus the frostbite tick at the next turn start (R p11) |
| `hand` | card utility: crisis-prevent symbols this round, symbols the objective counts, equips, food cards when `foodNeeded.shortfall > 0`, medicine when any own survivor has ≥2 wounds |
| `image` | how the action reads to a loyal observer running §8 on us: minus the evidence it would add (§8.2 table), plus the goodwill of visible help |

| Role | colony | objective | safety | hand | image |
|---|---|---|---|---|---|
| loyal, not exiled | 1.0 | 0.6 | 0.8 | 0.3 | 0.2 |
| loyal, exiled (E.11) | 0.3 | 1.2 | 0.8 | 0.3 | 0.0 |
| betrayer, hidden channels (§7) | −0.6 | 1.2 | 0.6 | 0.4 | 1.0 × cover (§7.3) |
| betrayer, visible channels | +0.5 | 1.2 | 0.6 | 0.4 | 1.0 × cover |
| betrayer, exiled | −0.8 | 1.5 | 0.5 | 0.3 | 0.0 |
| co-op variant | 1.0 | 0.0 | 0.8 | 0.3 | 0.0 |

Persona `risk` scales `safety` by `1 − 0.5·risk`; `generosity` scales `hand` by `1 − 0.5·generosity`.

### 3.4 Survivor and card values
- `value(survivor) = 10 + 2·influence/10 + 3·(6 − attack) + 3·(6 − search) + abilityValue + 4·[leader]`, halved for a
  survivor already at 2 wounds. A helpless token is worth 3 (it eats and dies to overruns, R p13).
- `value(card)` = max over uses: crisis prevent (+1 point ≈ `3·colonyWeight` when the margin is tight, 1 otherwise),
  objective symbol (per `parts` need), equip (its `EffectNode[]` through §10), food (`foodNeeded.shortfall` × 4),
  medicine (2 × wounded own survivors), plain discard value 0.5.

## 4. Dice knapsack (`plan.ts`)

### 4.1 Jobs and the search
A **job** is one survivor doing one thing with one die, after an optional move: `search@L`, `attackZombie@entrance`,
`attackSurvivor(target)`, `barricade@entrance`, `cleanWaste`, `attract(from…)`, `ability(id)`, or `idle`. The plan is
an assignment of unused dice (`seats[me].dice`) to jobs, with optional food boosts (`spendFood`, +1 per token on one
unused die, never above 6, F 5.3.1).

| Step | Detail |
|---|---|
| candidates | per survivor: every job at its location plus the top 3 destinations from §5; `query.dieRequirement` gives `need`, which dice qualify and `foodToReach` |
| job value | `U` of the job's outcome distribution (§4.2) minus die opportunity cost minus `foodToReach × foodValue` |
| search | beam over jobs ordered by value density (value ÷ dice used); width per tier (§12); each node = partial assignment; a die fits a job iff `value ≥ need` or `value + food ≥ need` with food left |
| bound | at most one move per survivor per turn (R p10); a survivor may attack or search several times with separate dice (R p8–9); abilities marked once per round check `abilityUses` |
| pick | the best full plan; the **first** action of that plan is returned (a move before its job, `spendFood` before the die is used) |
| re-plan | the engine raises `turnAction` again after every outcome; the planner rebuilds from the new view, so a search that found the card, a wound, or a Crossroads interruption changes the rest of the turn |
| end | `endTurn` when no job has value > 0 or no die is usable; the engine then asks `crisisContribution` (§6) |

A turn typically has ≤6 dice and ≤4 survivors: a player rolls 1 die + 1 per survivor they control (3 at the standard
start, 4 in the two-player variant where each player keeps 3 survivors), and Outsider cards, items, or abilities such as
Brian Lee (`DieAdded`) can push both counts past those typical values. Hard's beam normally finishes in a few
milliseconds at those sizes, but the planner never relies on the bound: the beam is capped only by the §14 time budget,
which checks the deadline between layers and degrades width before falling back, so an outlier turn with extra dice or
extra survivors stays within budget.

### 4.2 Closed-form odds (`odds.ts`)
Exposure faces on the d12: 6 blank, 3 wound, 2 frostbite, 1 bite (`EXPOSURE_FACE_COUNT`, rng.ts RULING; R p11 names
the faces). `query.exposureOdds` already applies grants (Sparky, Harman Brooks, Rod Miller, Mike Cho).

| Quantity | Formula |
|---|---|
| death on one roll, `w` wounds held | `pDeath(w) = bite + [w ≥ 2]·(wound + frostbite)`; frostbite also ticks +1 wound at the owner's next turn start (R p11) |
| survive `k` rolls | `Π_i (1 − pDeath(w_i))`, `w` advancing with the expected wound per roll |
| exposure cost | `pDeath·value(s) + (wound + frostbite)·woundCost(s) + bite·chainLoss(L)` |
| bite chain loss at `L` | survivors at `L` sorted by influence ascending: `V(i) = min(value(s_i), ½·0 + ½·(value(s_i) + V(i+1)))` from the choosing seat's view; `V(n) = 0` (R p11: kill, or roll; blank stops) |
| search: `n` draws, deck `R` cards left, `K` wanted | `P(hit) = 1 − C(R−K, n)/C(R, n)` from `query.searchOdds` (composition minus `seen`); expected draws to first hit for the keep-or-noise loop |
| noise token at `L` | `P(zombie) = 1/2` at the next colony phase (3 or lower on a d6, R p13); `cost = ½·zombieCost(L)` |
| attack a survivor | `pHit = targetAttack/6` (die ≤ the target's attack value, R p9); on a hit 1 wound and a random card (E[card] = the target's `handCount > 0` × prior card value); no exposure roll (R p9) |
| kill a zombie | `pKill = 1` with a qualifying die; cost one exposure roll (R p9) |
| crisis total | §6.1 |
| food token value | `colonyWeight × 3` when `foodNeeded.shortfall + tokens ≥ 1` next round, else 0.5 |

## 5. Movement risk (`moves.ts`)

Every move costs one exposure roll (R p10). A move is taken only when
`value(job at destination) − value(best job at home) > exposureCost(move) + returnCost + locationStep(L)`.

| Term | Source |
|---|---|
| `exposureCost` | §4.2 with the survivor's current wounds (`query.moveTargets` carries the odds) |
| `returnCost` | one more exposure roll later, discounted by `roundsLeft` (the survivor may simply stay) |
| `locationStep(L)` | one zombie per survivor at a non-colony location in the colony phase (R p13): `zombieCost(L)` × `1/(empty entrance spaces + barricades + 1)`; an overrun kills the lowest-influence survivor there |
| food credit | a survivor away from the colony does not eat (R p12): `+foodValue/2` |
| destination score | `query.searchOdds(L)` for the symbols wanted (crisis prevent first, then own objective, then food/medicine need); deck remaining; empty survivor spaces; zombies already there |

Bots keep survivors home when no die qualifies for a job elsewhere, barricade or clean waste with low dice, and
never move a 2-wound survivor unless the job is objective-critical.

## 6. Crisis contribution (`crisis.ts`)

The decision comes once per turn at `endTurn` (`crisisContribution`, 00 §16 RULING); the bot may also contribute
earlier as a turn action when it wants the table to see a card go in. Contributions are face down (R p11); the
reveal shuffles them (R p12), so what a seat "put in" is a claim until the recap.

### 6.1 Estimating the total
`T = myPoints + Σ_{s≠me} Σ_{cards of s} X_s`, with `X_s = +1` with probability `m_s`, else −1 (every card scores ±1, R p12).
- `m_s` = `0.85·(1 − S(s))` + `0.15·S(s)·0` for seats that already contributed (§8 suspicion); for seats still to play
  this round, the expected card count = `min(handCount, round(generosity_s × 1.5))` when the seat's persona is public
  (`seat.persona`), 1 for the human.
- `E[T]`, `Var[T]` in closed form; `P(T ≥ needed)` by the normal approximation (≥4 cards) or exact enumeration (<4).

### 6.2 Loyal rule
Contribute the smallest `k` matching cards with `P(T + k ≥ needed) ≥ τ_crisis` (§12), bounded by: never a card the
own secret objective still counts (unless `P(prevent) < 0.3` and the fail effect costs ≥2 morale), never more than
`needed + 2 − E[T]` (over-contributing removes cards from the game, R p12), and the optional bonus only when the extra
cards are plain (`value < 1`). Contributed cards come from the hand first, equipped items last.

### 6.3 Saying what went in
After contributing, the bot emits `crisis.contributed {count, symbol}` (41): truthful with probability
`1 − bluffing`; a betrayer always claims matching cards. Other bots weigh the claim by their `trust` (§8.2).

## 7. Betrayer play (`betrayer.ts`)

### 7.1 Lever
Each betrayal objective record carries an `ai.lever` hint (`20-data-schema`): `moraleZero`, `hoard:<symbol>`,
`killSurvivors`, `zombiesAtColony`, `exileOthers`, `starve`, `custom`. The objective component of §3 scores progress
along that lever; `query.objectiveProgress` supplies `parts`.

### 7.2 Channels
| Hidden (colony weight −0.6) | Visible (colony weight +0.5, image +) |
|---|---|
| wrong-symbol cards into the crisis (the pile is shuffled, R p12) | killing zombies, barricading, cleaning waste |
| hoarding the symbol the objective needs; "searching" where it is rare | moving to where help is visibly needed |
| declining requests with a plausible reason (§9.2) | giving a low-value card when asked |
| the colony-harming Crossroads option when the other was also plausible | truthful-looking claims (§6.3) |
| attracting zombies to a location with other seats' survivors only when a loyal reading exists (clearing the colony gate) | calling a vote on a seat that looks worse than itself (Hard only) |

### 7.3 Cover budget
`cover = θ_vote − max_s Ŝ_s(me)`, where `Ŝ_s(me)` is §8 run on the bot's own public record from seat `s`'s side
(a bot's persona paranoia when `s` is a bot, Normal paranoia for the human). Each hidden move has an evidence cost
from the §8.2 table; the bot takes it iff `cost ≤ cover × margin` or the vote no longer matters (`roundsLeft ≤ 1`,
or morale ≤ 1 with a `moraleZero` lever). `margin` per tier (§12). When `cover < 0` the betrayer plays loyal until it
recovers. It never votes itself out and always votes the hidden interest (§8.4).

### 7.4 Tells the human can read (and the recap shows)
Crisis maths (cards in vs points revealed, `query.crisis`), who was where when zombies came, who always declines,
who keeps the symbol the objective needs, who chose the costly Crossroads option. At game end `view.recap` lists
every contribution by seat and every secret objective (C.4).

## 8. Suspicion model (`suspicion.ts`)

Every bot keeps `S(s) ∈ (0, 1)` for every other seat, stored as log-odds `L(s)`, updated from public events
(`redactEvent`-visible ones only) after every step the client forwards (§14).

### 8.1 Prior
`P(seat s is the betrayer) = 1/(2n + 1)` with `n` seats (one betrayal card among `2n + 1` dealt `n`, R p6);
`1/(n + 1)` in the betrayer variant; 0 in co-op (no secret objectives, R p15). `L₀ = ln(p/(1 − p))`.

### 8.2 Evidence (Δ in log-odds; positive Δ scaled by `paranoia`, statement rows by `trust`)
| Key | When | Δ (Normal) |
|---|---|---|
| `crisis.shortfall` | after `CrisisResolved`: `wrong = (cards − total)/2` wrong cards, minus any the bot itself put in; split over contributing seats ∝ `contributionsBySeat` | +0.9 per attributed wrong card |
| `crisis.none` | a seat with `handCount ≥ 3` contributed 0 to a crisis that failed | +0.3 |
| `request.declined` | declined while likely holding the card (seen via `CardStolen` to us, an earlier `CardGiven`/`CardPlayed`, or a search at a location where that symbol leads the order) | +0.5 |
| `crossroads.hurt` | `CrossroadsResolved {forced: false}` picking the option with lower colony value (§10) | +0.6 |
| `attract.others` | `ZombieMoved` by a seat's survivor toward a location holding other seats' survivors | +0.7 |
| `attack.survivor` | `SurvivorAttacked` on a non-exiled seat's survivor | +1.2 |
| `colony.hungry` | ended a turn with `foodNeeded.shortfall > 0` while holding ≥4 cards and playing none | +0.3 |
| `hoard` | `handCount` grew ≥2 this round with no contribution and no card played | +0.2 |
| `claim.consistent` | a seat's `crisis.contributed` claim fits the revealed total | −0.2 × trust |
| `claim.broken` | the claims of the contributing seats sum above the revealed total; split like `crisis.shortfall` | +0.5 × trust |
| `accused` | a seat accuses `s` (human accusation or a bot lean, §9.3) | +0.2 × (1 − S(accuser)) × paranoia |
| `accuser.deflects` | the accuser is already the most suspected seat | +0.1 on the accuser |
| `help.visible` | zombie killed, barricade, waste cleaned, card given | −0.1 each, capped −0.3 per round |
| `crisis.prevented` | the seat contributed to a prevented crisis | −0.2 |

Per seat and round the net update is clamped to ±1.5. There is no decay: evidence accumulates for the game.

### 8.3 Scalars (41 §1)
`paranoia ∈ [0.5, 1.6]` multiplies every positive Δ; `trust ∈ [0, 1]` multiplies the statement rows. A betrayer runs
the same model to know whom the table suspects, and runs it on itself for §7.3.

### 8.4 Vote and call rules
| Rule | Detail |
|---|---|
| vote yes on `s` | `S(s) ≥ θ_vote` **and** the colony can afford it: `afford = morale ≥ 3 ∧ (dice lost (survivors + 1) ≤ ⅓ of table dice ∨ roundsLeft ≤ 1 ∨ main objective ≥ 80%)`; exiled seats cannot vote (R p14) |
| never | yes on itself (cannot even call it, R p11); a betrayer never votes against its hidden interest: it votes yes on loyal seats when that helps its lever (two exiled non-betrayers end the game at morale 0, R p14) and no otherwise |
| tie | the first seat breaks ties (R p11): the bot reads `query.voteForecast(target).tiebreakBy` |
| call a vote | once per turn (R p11): iff `S(s) ≥ θ_call` and the estimated yes count ≥ `needed`, estimating each other seat's `S` as its own `S(s) × 0.6` (public evidence, private thresholds); the Hard betrayer may call on the most-suspected loyal seat when `cover` allows |
| lean | before any vote the bot emits `vote.lean.yes/no/silent` by persona `chattiness` (H.5), from the same rule |

Benchmark: exile accuracy (§13).

## 9. Social actions (`social.ts`)

### 9.1 Requests (R p11)
At most one `request` per turn, when the plan wants a symbol the hand lacks (crisis prevent with `P(prevent) < τ_crisis`,
an objective part, an ability cost per F 5.2.1). Target = argmax over seats of `P(holds) × E[gives]`, where
`P(holds)` comes from `handCount` and the evidence rows of §8.2 and `E[gives]` from the seat's persona `generosity`
(0.5 for the human) × `(1 − S(s))`. A given card is revealed and played at once and cannot go to the crisis
(R p11; RULING in `docs/needs-rules-check.md`), so a request never asks for crisis cards directly: it asks for the
effect (food, medicine, fuel for an ability).

### 9.2 Answers
Give the lowest-value matching card iff `value(card) ≤ generosity × 3 × (1 − S(requester))` and the play helps the
colony (§3). A betrayer declines whenever the play would help the colony, unless `cover` is low (then gives the
cheapest). Every decline is `request.decline` evidence to the others, so Normal and Hard loyal bots give more often
than Easy.

### 9.3 Accusations (table talk only, no rules effect)
A human accusation or a bot lean is an `accused` row (§8.2) on the target and may add `accuser.deflects` on the
accuser. The accused bot emits `accused.me`; a third bot may emit `accused.other` (41 frequency caps).

## 10. Option valuation (`options.ts`)

Crossroads, objective, item and effect choices are `EffectNode[]` lists from the bundle. `options.ts` folds each
list into goal deltas with a static table (no `step` is available from a view) and scores with §3.

| `EffectOp` | Δ (per unit, on the scoped targets) |
|---|---|
| `morale` | colony ±10 per point |
| `food` / `starvation` | colony ±`foodValue` / ∓6 |
| `addZombies` / `killZombies` / `moveZombies` | ∓`zombieCost(L)` per zombie (§5); attract rules: empty spaces only (F 5.1.1) |
| `addBarricade` / `removeBarricade` / `addNoise` / `removeNoise` | ±`zombieCost(L)/2` / ±`½·zombieCost(L)` per token |
| `wound` / `heal` / `exposure` / `killSurvivor` / `removeSurvivor` | safety via §4.2 on each target; `removeSurvivor` costs no morale (E.7) |
| `addSurvivor` / `addHelpless` / `removeHelpless` | +`value(new)` − food share; helpless ±3 and food |
| `draw` / `drawFromDeck` / `discard` / `removeCard` / `giveCard` / `stealCard` / `contribute` | hand ±`E[value(card)]` |
| `peekDeck` / `revealDeck` / `shuffleDeck` / `extraSearchKeep` / `extraSearchLook` | hand +0.5–2 (search odds improvement) |
| `modDie` / `addDie` / `refundDie` | +`value(best job the die unlocks)` |
| `forbid` / `grant` / `treatFaceAs` | lasting: the §4.2 odds difference × remaining rolls expected (`roundsLeft × 1.5`) |
| `choose` | max over its options; `vote` → §8 forecast; `exile` → −∞ for self; `endGame` → ±∞ by own objective state |
| `{code}` nodes | a per-code value in a registry; unknown codes score 0 and are logged in the bench |

A betrayer scores the same table with its role weights, then applies the §7.3 budget: the harming option is taken
only when `P(forced-looking)` is high (the other option also costs the colony, or the human cannot see the alternative's
value).

## 11. Talk intents (`talk.ts`)

The decider returns an `Action`; alongside it (worker `trace.talk`, §14) it may emit
`TalkIntent {key, slots, truthful}` where `key` is an event key from `41` §3 and `slots` hold only public ids and
numbers from the bot's **own** view plus claims about its own play. The line bank renders them (41 §3–§5).
Intents never carry another seat's hidden ids (the leak test runs on serialised intents too), and never state the
bot's own secret objective or hand contents, only claims (`crisis.contributed`) that the suspicion model treats as
statements.

## 12. Tiers (`tiers.ts`)

| Tier | Planner | Beam | τ_crisis | Suspicion | Betrayer | θ_vote / θ_call | Extras |
|---|---|---|---|---|---|---|---|
| `random` | uniform over `legal` (`createRandomDecider`) | — | — | none | none | never votes yes | sim and fuzz |
| `easy` | greedy (width 1), score noise σ = 15%, no food boosts beyond 1 token | 1 | 0.5 | none; votes yes only on `attack.survivor` evidence | greedy: `margin = ∞`, sabotages from round 1 | 0.9 / 0.95 | requests never, gives by generosity alone |
| `normal` | full plan, closed-form odds | 4 | 0.7 | full §8 | `margin = 0.8` | persona (41 §1) | leans before votes |
| `hard` | normal + others' contribution estimate uses hand-tracking (seen cards, search locations) and 1-ply lookahead on the crisis total | 8 | 0.75 | full, + claim tracking across rounds | `margin = 0.5`, patient: sabotages only when ≥2 other seats contributed (diffuse shortfall), frames, may call deflecting votes | persona − 0.05 | plans the objective symbol over two rounds |

Persona scalars (41 §1) apply at `normal` and `hard`; `easy` uses them at half strength; `random` ignores them.

## 14. Time budget and worker

- **Budget.** `DOW_AI_BUDGET_MS` (default 500; sim default 200; hard cap 2000). The planner checks the deadline between
  beam layers and degrades: width → 1, then the greedy policy, then `legal[0]`; the bench counts each degradation.
- **Worker.** `src/ai/worker.ts`, a module worker (`new Worker(new URL('./worker.ts', import.meta.url), {type:'module'})`).
  Messages: `init {bundle, seed, seats: {seat, tier, persona}[]}` → `ready`; `decide {seat, view, pending, legal}` →
  `{action, talk?: TalkIntent[], trace?}`; `observe {seat, events: GameEvent[]}` (already redacted for that seat) feeds
  §8; `talk {seat, view, event}` → `TalkIntent[]` for reactions that are not decisions. `trace` (debug) carries the
  top-3 candidates with scores and the current `S(s)` row for the `?test=1` overlay.
- One worker hosts every bot seat; each seat's suspicion ledger and plan cache are keyed by seat and never shared.
- The client calls `decide` only when presentation is idle (C.5) and times out at 2 s → the easy policy on the main
  thread, else `legal[0]`, logged. The store's 5 s watchdog (00 §13) is the last resort.
- For `votes` (`pending.seat === 'all'`) the store sends one `decide` per bot seat with that seat's view and assembles
  `castVotes`; bots never see the human's vote first (C.4).
- `npm run sim` and the bench run the same code in-process; the worker is a transport, not a policy.
